# クロスポータル・多媒体横断名寄せ（ファジーデデュープ）仕様 (Cross-Portal Deduplication & Fuzzy Matching)

## 1. 概要と背景
22社以上の大手不動産会社および Homes, Athome などのポータルサイトを横断してクロールする際、各社で表記が異なる同一物件を正確に名寄せ（重複排除・Upsert統合）し、同一物件の重複登録（Duplicate Explosion）とSlackへのスパム通知を根絶する。

---

## 2. 複合名寄せキーとスコアリングモデル

単純な文字列完全一致（Exact Match）では、番地省略や建物名略称により名寄せ漏れが発生するため、以下の「多層階層型スコアリング」を採用する。

### 2.1 判定項目と重み付け

| 比較項目 | 照合アルゴリズム | 一致時のスコア | 許容誤差・ルール |
| :--- | :--- | :--- | :--- |
| **所在地 (正規化後)** | 都道府県・市区町村・町丁目までの一致 | **40点** | 完全一致が前提条件（都道府県・市区町村不一致は即 0点） |
| **番地・号** | 番地・号の正規化比較 | **20点** | 一方が「番地非公開」の場合は保留（減点なし） |
| **専有面積 / 土地面積** | 数値差分比較 | **20点** | **±0.5㎡（約0.15坪）以内** の誤差は同一とみなす |
| **階数 / 所在階** | 数値比較 | **10点** | 一致で加点（戸建て・土地はスキップ） |
| **建物名** | Levenshtein距離 / Jaro-Winkler類似度 | **10点** | 類似度 0.85 以上、または前方一致で加点 |

### 2.2 統合・Upsert判定基準
- **合算スコア 85点以上**: **同一物件認定（`IS_DUPLICATE`）**
  - 新規レコードは作成せず、親物件（既存レコード）の `PropertySourceHistory` に新媒体情報（URL、媒体名、最新確認日時）を追記・更新（Upsert）する。
- **合算スコア 70〜84点**: **重複候補（`POTENTIAL_DUPLICATE`）**
  - 同一物件の可能性があるため、Slack通知は親物件とグループ化し、別物件としての単体発報を抑止する。
- **合算スコア 70点未満**: **別物件（`UNIQUE`）**
  - 新規物件として登録。

---

## 3. 親子関係と優先度ルール (Master Source Selection)
同一物件が複数サイトに掲載されている場合、物件マスタ（親レコード）のスペック情報は以下の優先度ルールに従って信頼性の高いデータで上書き・補完する。

1. **元付・大手自社サイト優先**: 三井・住友・東急などの自社サイトの情報を、ポータル（Homes/Athome）の情報よりも優先する。
2. **情報リッチ度優先**: より多くの詳細スペック（管理費・修繕積立金・接道幅員等）が記載されている方のデータを優先採用する。
