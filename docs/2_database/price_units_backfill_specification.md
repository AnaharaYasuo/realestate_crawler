# データベース価格単位正規化仕様書 (Issue #1291)

## 1. 概要と背景
各物件モデルのクローリングデータにおいて、原本文字列 `priceStr`（例: `5,280万円`, `130,000万円`）からパースされた値が、一部クローラーの不具合により「万円単位」（例: `5280`, `130000`）のまま `price` カラムに保存され、円単位（例: `52800000`）と混在していた。

これにより、ML 学習データローダー（`data_loader.py`）が一律 `/ 10000.0` する際に `price = 0.528`（5,280円）等に縮退し、クレンジング処理（`price > 50`）によって全データの約 24%（土地では 36%）が「異常値」として不当に物理除外されていた。

## 2. 復旧方式（原本完全一致再パース型）
ヒューリスティックな数値閾値（例: `< 50000`）による一律掛け算は、境界帯（10万円〜50万円の格安物件 vs 10億円〜50億円の超高級物件）で誤爆を招くため禁止。
各レコードが保持する原本文字列 `priceStr` に対し `package.utils.converter.parse_price` を実行し、完全一致での再パース結果で `price` カラムを一括更新（`bulk_update`）した。

### 実行実績 (2026-11-07 実施)
- **走査対象**: 55,537 件 (`price < 500,000`)
- **修復完了件数**: **53,270 件**（原本から正確に円単位へ復旧）
  - 三井不動産リアルティ: マンション 7,597 件、戸建て 2,893 件、土地 3,799 件
  - 住友不動産ステップ: マンション 10,946 件、戸建て 9,335 件、土地 12,440 件
  - 東急リバブル: マンション 6,260 件
- **変更不要（既に円単位）**: 2,267 件
- **パース失敗（欠損等）**: 0 件（100% 成功）

## 3. 効果検証
- **物理制限除外率**:
  - 土地モデル（tochi）: 3,000 件中 1,106 件除外 (36.8%) ➔ **わずか 18 件除外 (0.6%) へ激減**
  - 有効学習データ数: 1,757 件 ➔ **2,785 件（約 1.6 倍に激増）**
- **モデル実測精度指標 (tochi)**:
  - CatBoost MAPE: 47.1% ➔ **41.4%** (約 5.7 pt 改善)
  - Median APE: 28.3% ➔ **25.2%** (約 3.1 pt 改善)
  - 決定係数 $R^2$: 0.675 ➔ **0.710**
