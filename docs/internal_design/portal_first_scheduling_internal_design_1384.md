# 内部設計書: 大規模ポータル先行起動によるロングテール解消と優先度スケジューリング改善 (Issue #1384)

## 1. 概要・背景
ローカル本番実行やバッチクローリングにおいて、物件掲載数が数万件規模かつ Playwright によるステルス描画を要する大規模ポータルサイト（`athome`, `homes`）が存在する。
従来の優先度スケジューラ（`crawler_scheduler.py`）では、大手仲介5社や信託系（`mitsui`, `sumifu`, `tokyu`, `nomura` 等）を最優先（Tier 1）として先にキューから取り出し、ポータル系が後回しになっていた。
この結果、高速に終わる中小・大手各社のジョブが完了した終盤にポータル系ジョブだけが残り、並行実行スロットの大部分が空いているにもかかわらずポータル単体の完了を長時間待機する「ロングテール問題（ボトルネック）」が発生していた。

## 2. 改善方針
- **大規模ポータル最優先投入 (Longest-Job-First / Critical-Path-First)**:
  - 処理所要時間が最も長いメガポータル（`PORTAL_COMPANIES = {"athome", "homes"}`）をキューの最前列（最優先）に配置する。
  - パイプライン開始直後の最初の並行枠からポータルを稼働させ、裏で長時間かけて安定先行消化させる。
  - 同時に、大手仲介5社・信託系・中小各社も残りの並行スロットで並行して消化されるため、全体の総所要時間が大幅に短縮される。
- **リソース保護と並行度上限の遵守**:
  - `select_next_job` による会社別並行度上限（`athome: 3`, `homes: 5` 等）および Playwright 全体並行数上限（`max_playwright_parallel`）は厳格に維持し、OOM や過剰負荷を確実に防止する。

## 3. 実装詳細

### 3.1 `calculate_job_priority` の優先度タプル見直し (`src/crawler/package/utils/crawler_scheduler.py`)
優先度ソートキー（タプル）を以下のように更新する：

1. **軸0 (自タスク主担当大手)**: `host_company` と一致する会社 -> 2, その他 -> 0（Task Array 環境での担当優先）
2. **軸1 (大規模ポータル先行)**: `athome` / `homes` -> 3, 主要仲介大手（三井・住友・東急等） -> 2, その他一般仲介 -> 1
3. **軸2 (種別重み)**: `mansion` -> 3, `kodate` -> 2, `tochi` -> 1, その他（投資等） -> 0

これにより、ポータルがキューの先頭に来て即座にスロット上限まで起動され、空いたスロットに主要仲介やその他が投入される。

### 3.2 ユニットテストの強化
- `src/crawler/tests/unit/test_crawler_scheduler.py` に、`athome` / `homes` が主要仲介より先にキュー先頭にソートされること、および並行度上限に達した際は正しく次点の大手仲介が選択されることを検証するテストケースを追加・更新する。
