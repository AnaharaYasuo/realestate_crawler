# 価格推定精度・ズレ日次診断ポリシー (Daily Prediction Diagnostics Policy)

## 1. 目的と理念 (Purpose & Principles)

本ドキュメントは、不動産価格推定パイプラインにおける理論価格推論（一次・二次）と実際の売出価格・成約相場との「ズレ（推定誤差）」を日次で可視化・分析し、継続的にモデルおよびデータ抽出精度を改善するための運用方針を定めます。

不動産価格の推定ズレは、単なるアルゴリズムのハイパーパラメータの問題にとどまらず、**「パーサーによる特異条件（借地権・再建築不可等）の抽出漏れ」「学習データの外れ値汚染」「地域マイクロマーケットの非線形性」** に起因することが大半です。
したがって、本ポリシーでは**「日次診断結果に基づくパーサー修正・データクレンジング・特徴量拡充の即日PDCAループ」** を最重要視します。

---

## 2. 評価指標 (KPI Definitions)

外れ値や億ション等の超高額物件による平均値の歪みを防ぐため、主指標として中央値ベースの指標を採用します。

| 指標名 | 略称 | 定義・計算式 | 採用理由・目標値 |
| :--- | :--- | :--- | :--- |
| **中央値絶対パーセント誤差** | **MdAPE** | $\text{Median}\left( \left\| \frac{\hat{y}_i - y_i}{y_i} \right\| \right) \times 100$ | **主KPI**。極端な外れ値に引きずられない実力精度。<br>**目標: 12.0% 以下** |
| **平均絶対パーセント誤差** | **MAPE** | $\frac{1}{n}\sum_{i=1}^n \left\| \frac{\hat{y}_i - y_i}{y_i} \right\| \times 100$ | 全体の乖離水準の把握。<br>**目標: 18.0% 以下** |
| **二乗平均平方根誤差** | **RMSE** | $\sqrt{\frac{1}{n}\sum_{i=1}^n (\hat{y}_i - y_i)^2}$ | 金額ベース（万円）の絶対誤差把握。 |
| **±10%以内適合率** | **Hit Rate @ 10%** | $\frac{\text{Count}\left( \left\| \frac{\hat{y}_i - y_i}{y_i} \right\| \le 0.10 \right)}{n} \times 100$ | 実用的な高精度帯（お宝物件判定のコア）。<br>**目標: 45.0% 以上** |
| **±20%以内適合率** | **Hit Rate @ 20%** | $\frac{\text{Count}\left( \left\| \frac{\hat{y}_i - y_i}{y_i} \right\| \le 0.20 \right)}{n} \times 100$ | 許容誤差範囲内のカバー率。<br>**目標: 75.0% 以上** |

## 3. 日次セグメント分析基準 (Segmentation Dimensions)

全体平均の指標のみでは、特定セグメント（例: 地方戸建や超高級タワマン）の精度悪化を見落とすため、日次診断スクリプトでは以下の3軸で分解集計を行います。

### 3.1 物件種別 (Property Type)
- `mansion` (区分マンション)
- `kodate` (一戸建て)
- `tochi` (土地)
- `apartment` (一棟アパート・投資用)

### 3.2 価格帯 (Price Tier)
- **低廉帯**: ~3,000万円未満（地方・築古中心。分母が小さいためパーセント誤差が跳ねやすい）
- **主力帯**: 3,000万円以上〜1億円未満（市場取引のボリュームゾーン）
- **高額帯**: 1億円以上〜3億円未満（都心タワーマンション、高級住宅地）
- **超高額帯**: 3億円以上（個別要因が強く、単位換算バグや外れ値の影響を受けやすい）

### 3.3 エリアセグメント (Geographical Tier)
- **都心コア**: 東京都 千代田区・中央区・港区・新宿区・渋谷区
- **東京23区周辺**: 23区他18区
- **首都圏近郊**: 神奈川県、埼玉県、千葉県
- **地方・その他**: 上記以外の全国エリア

## 4. 乖離ワースト物件のクラスタリング・原因究明基準

日次で **誤差比率 $\pm 20\%$ を超えるワースト物件（上位各5〜10件）** を自動抽出し、以下のルールに基づき原因を自動推定（タギング）します。

```mermaid
flowchart TD
    ErrorItem["誤差 ±20% 超物件"]
    ErrorItem --> Direction{"上方乖離 or 下方乖離"}
    
    Direction -->|上方乖離 (推論 > 実価格)| Over[過大推論クラスタ]
    Direction -->|下方乖離 (推論 < 実価格)| Under[過小推論クラスタ]
    
    Over --> C1["借地権・旧法借地・定期借地 のパース漏れ"]
    Over --> C2["再建築不可・市街化調整区域 のパース漏れ"]
    Over --> C3["告知事項（事故物件・心理的瑕疵）の未検知"]
    Over --> C4["狭小地・旗竿地・崖地・接道不良"]
    Over --> C5["売出ダミー安値・競売落札案件"]
    
    Under --> U1["フルリノベーション・内装一新 のパース漏れ"]
    Under --> U2["ブランドタワー・所在階プレミアム（最上階等）"]
    Under --> U3["角地・二面接道・整形地 プレミアム"]
    Under --> U4["売主強気値付け・長期滞留物件"]
```

### 4.1 上方乖離（過大推論: 推論価格 $\gg$ 実売出価格）
- **特徴**: モデルが通常相場（所有権・整形地）で評価しているが、実際は大幅な減価要因が存在する。
- **主要因と検出キーワード**:
  - `leasehold`: 「借地権」「旧法借地」「地上権」「定期借地」「地代」
  - `unbuildable`: 「再建築不可」「市街化調整区域」「建築確認不可」「要セットバック」
  - `hazard_stigma`: 「告知事項あり」「心理的瑕疵」「特別募集」
  - `shape_penalty`: 間口2m未満、旗竿地、敷地延長、傾斜地

### 4.2 下方乖離（過小推論: 推論価格 $\ll$ 実売出価格）
- **特徴**: モデルが築年数・駅距離のみで低く見積もっているが、実際は付加価値が存在する。
- **主要因と検出キーワード**:
  - `renovated`: 「リノベーション」「新規内装リフォーム」「フルリノベ」「給排水管更新」
  - `premium_tower`: 階数20階以上、最上階、角部屋、ルーフバルコニー
  - `overpriced_seller`: 売却急がず相場無視の売出価格（売出後1年以上滞留）

## 5. 日次運用・ブラッシュアップループ (Daily PDCA Loop)

毎日のクローリングおよびバルク推論の直後に、以下の日次改善サイクルを自律的に回します。

```
[毎朝 06:00: パイプライン Phase 1 完了]
  │
  ├─► [Step 1: run_daily_prediction_diagnostics.py 実行]
  │     ・最新DBの PropertyEvaluation をスキャン
  │     ・種別・価格帯別の MdAPE / Hit Rate を算出
  │     ・ワースト10件の原因自動タギング
  │     ・AI (Gemini Flash) によるワースト物件の乖離要因深掘り＆改善提案
  │     ・日次レポート (JSON/Markdown) 出力
  │
  ├─► [Step 2: Slack 自動レポート (#alerts-ml)]
  │     ・種別別スコアカード（前日比 ±Δ）
  │     ・AI による分析サマリー ＆ ワースト5件のURL・推定原因のダイジェスト投稿
  │
  ├─► [Step 3: 原因究明 & 即日パッチ (Auto-Healing / 開発)]
  │     ・AI提案の改善アクション（借地権パース修正、リノベ特徴量追加等）を即日反映 (SDD×TDD)
  │     ・異常値・入力ミス ➔ 学習用外れ値除外フィルタに追加
  │
  └─► [Step 4: ポリシーと診断スクリプトのブラッシュアップ]
        ・新奇なズレ要因を本ポリシーのタギングルールへ追記
        ・診断スクリプトの検知ロジックを更新
```

## 6. 単位同調・データクレンジングの原則 (Unit Coherence)

1. **推論値単位の不変則**:
   - `predict.py` 内のモデル出力 (`predicted_price`) は **100% 万円単位** である。いかなる場合も `predicted_price` に対する 10,000 除算を行ってはならない。
2. **実売出価格 (`actual_price`) の動的判定則**:
   - `actual_price >= 100,000`（10万円以上）の場合は「円単位」と判定し、`actual_price / 10000.0` により万円単位に統一する（63万円等の格安物件が万円誤認されるのを防止）。
   - `0 < actual_price < 100,000` の場合は「万円単位」と判定し、除算せずそのまま採用する。

## 7. AIを活用した日次自動診断・考察 (AI-Powered Diagnostics)

コスト効率の高い AI モデル（Gemini 1.5 Flash / Gemini 2.0 Flash 等）を活用し、日次診断結果に対するインサイト自動生成を行います。

### 7.1 AI分析の責務
1. **ワースト乖離物件の自然言語分析**:
   - 物件タイトル、備考欄、所在地、間取り、築年数、および推論特徴量をプロンプトに入力。
   - モデルが「なぜこの価格を予測し、なぜ実価格と乖離したか（隠れた価値、未抽出の減価要因）」を不動産鑑定士視点で考察。
2. **パーサー・特徴量への即日改修アクション提案**:
   - 「〇〇パーサーで『借地権』の抽出正規表現を追加すべき」「『フルリノベーション』を拾う特徴量が必要」など、開発者が即日着手できる具体的修正方針を出力。
3. **Graceful Fallback 原則**:
   - APIキー未設定時やネットワーク障害時は、ルールベースの自動タギングでレポート生成を完結させ、全体の診断パイプラインを停止させない。
