# タスクアレイ完了時のプロセス即時終了保証および最終タスクへの全体集約委譲 外部設計書 (Issue #823)

## 1. 外部インタフェースと動作フロー

### 1.1 先行完了タスク（Worker / Coordinator 問わず）
1. 自タスクの割り当てジョブ（`target_jobs`）がすべて終了する。
2. 自タスクの実行結果サマリーを作成し、DB（`CrawlerTaskExecution`）に保存（`COMPLETED` または `FAILED`）。
3. DB から今回の実行 ID（`execution_id`）に属する他タスクの状態を取得。
4. **未完了タスク（`RUNNING` 等）が1件以上存在する場合**:
   - `logger.info("✔ 他タスクが実行中のため全体集計・レポート送信をスキップし、即時終了します。")` を出力。
   - `monitor_error_pages.py` 呼び出し、および `db_summary`（全社テーブルカウントクエリ）を完全スキップ。
   - `shutdown_new_relic()` を呼び出し、直ちに `sys.exit(0)` で正常終了。

### 1.2 最終完了タスク（最後に終わった1台）
1. 自タスクの割り当てジョブがすべて終了する。
2. 自タスクの実行結果サマリーを作成し、DB（`CrawlerTaskExecution`）に保存。
3. DB から他タスクの状態を取得。
4. **自タスク以外の全タスクがすでに `COMPLETED` または `FAILED` である場合（自分が最後の1台）**:
   - `logger.info("✔ 全タスク完了を検知（最終タスク）。全体集約レポート送信およびエラーページ監視を実行します。")` を出力。
   - 代表して過去24時間の全社取得件数集計 (`db_summary`) を実行。
   - 全タスクの実行結果を反映した総合クローリング状況レポートをSlackへ1通送信。
   - `monitor_error_pages.py` を実行。
   - 必要に応じて共有 ProxySQL の停止判断（`_can_stop_shared_proxysql()` が True になるため停止実行）を行い、`sys.exit(0)` で正常終了。

### 1.3 単体タスク実行（`task_count <= 1`）
- 分散実行ではないため、常に自分が唯一のタスクとして全体集計・レポート送信・エラー監視を実行（後方互換性100%維持）。

## 2. Slack 通知の変更点
- **変更前**: タスクアレイ 5 並列の場合、完了した各タスクが「クローリング実行状況レポート (Task X/5)」を 5 回個別に送信。
- **変更後**:
  - 各ジョブ単位の「開始/成功/失敗」通知は現行どおり送信。
  - 「クローリング実行状況レポート」は、全タスクが完了した瞬間に**最後の1台から1通のみ**総合レポートとして送信。
  - レポート内容には、全担当ジョブ数・成功数・失敗数の総計と、過去24時間新規取得件数が網羅される。
