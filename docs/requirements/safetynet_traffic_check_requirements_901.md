# 要件定義書: ProxySQL中断判定におけるトラフィック閾値チェック機能 (#901)

## 1. 背景と課題
- ローカル環境等から IAP トンネル経由で ProxySQL に接続し、本番データ投入（`run_pipeline.py`）を実行している際、毎時0分発火のゾンビ課金防止ジョブ（`realestate-safety-net-daily-prod`）によって ProxySQL VM が強制停止されてしまう事象が発生した。
- 現行の判定ロジック（`ensure_resources_stopped.py`）は Cloud Run Job の稼働状況のみを監視しており、Cloud Run Job が 0 件であれば即座に「停止漏れの孤立インスタンス（ゾンビ）」とみなして ProxySQL を停止していた。
- これにより、ローカル本番実行が突然の DB 接続断で中断してしまう。

## 2. 要件
- **REQ-001 (アクティブトラフィック判定)**: Cloud Run Job が 0 件であっても、ProxySQL VM において直近 10 分間のネットワーク受信バイト数が閾値（デフォルト 1 MB = 1,048,576 バイト）以上存在する場合、ローカルまたは外部からアクティブなクエリ通信が行われていると判断し、ProxySQL インスタンスの強制停止を安全にスキップすること。
- **REQ-002 (ヘルスチェック等の微小トラフィック誤判定防止)**: ProxySQL 内部で発生する Cloud SQL へのヘルスチェック（10秒に1回の ping、10分で数十KB程度）を「稼働中」と誤判定しないよう、1 MB 未満の通信量であればアイドルとみなして停止対象とすること。
- **REQ-003 (最大連続稼働時間によるハング防止)**: 通信が継続している場合であっても、ProxySQL の連続稼働時間が上限（デフォルト 8 時間 = 28,800 秒）を超過した場合は、ハングや放置による課金爆発を防止するため強制停止すること。
- **REQ-004 (環境適応とフォールバック)**: Cloud Monitoring API や認証が利用できない場合（ローカルテスト環境等）、例外で全体がクラッシュせず安全にフォールバックすること。
