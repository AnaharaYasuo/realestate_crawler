# CI/PR 監視における無制限 --watch 禁止および有限タイムアウトポーリング強制 要件定義書 (Issue #602)

## 1. 概要と背景
GitHub Actions CI（PR checks、Production Gate等）を監視する際、`gh pr checks <PR_NUM> --watch` などの無制限待機コマンドを使用すると、GitHub側のジョブスタック（`action_required`、手動承認待ち、ランナー不足等）によってコマンドが永久にブロック・ハングし、AIエージェントの作業停止やユーザーへの長時間放置を引き起こす。
本要件はこれを根絶し、すべてのCI監視・PRチェック確認において「無制限 `--watch` の全面禁止」と「有限タイムアウト付きポーリング監視」を強制するための仕様を定める。

## 2. 機能要件 (FR)
- **FR-001 (無制限 --watch コマンドの全面禁止)**:
  - 開発者・AIエージェントによる `gh pr checks --watch` や `gh run watch` 等の無制限ブロック待機コマンドの実行を全面禁止すること。
  - プロジェクト共通ルール（`AGENTS.md`）およびワークフロースキル（`SKILL.md`）に禁止事項として明記すること。
- **FR-002 (有限タイムアウト指定と定期ポーリング強制)**:
  - PR checks の状態確認は、単発の `gh pr checks <PR_NUM>` を有限タイムアウト（CLI実行タイムアウト上限10秒以内）で実行するか、有限タイムアウト・インターバル付きの専用ポーリング監視スクリプト（`check_pr_ci_status.py`）を使用すること。
- **FR-003 (スタック・保留状態の即時検知と自己診断)**:
  - ジョブが `action_required`、`stalled`、または失敗（`fail`）になった場合、無限に再試行や待機を続けず、即座に該当ジョブの詳細（`gh run view <run-id>`）を取得して原因（再実行が必要か、手動承認待ちか等）を診断・報告すること。
- **FR-004 (CIステータス監視スクリプトの提供)**:
  - PR番号を受け取り、最大試行回数（`--max-attempts`、デフォルト15回）およびポーリング間隔（`--interval`、デフォルト15秒）でCIステータスを監視するCLIスクリプト `src/crawler/scripts/debug_tools/check_pr_ci_status.py` を提供すること。
  - 各API・コマンド呼び出しには必ず10秒以内の有限タイムアウト（`timeout=10`）を強制すること。

## 3. 非機能要件 (NFR)
- **NFR-001 (プロセスハングの完全根絶)**:
  - 外部ネットワーク遅延やGitHub障害時にも、スクリプトおよびエージェントが無限待機（ハング）せず、必ず有限時間（最大でも指定タイムアウト内）で制御を戻すこと。
- **NFR-002 (テスタビリティ)**:
  - PRステータス判定（pending, pass, fail, action_required）およびタイムアウト処理が単体テスト（`pytest`）で100%検証可能であること。
