# タスクアレイ完了時のプロセス即時終了保証および最終タスクへの全体集約委譲 要件定義書 (Issue #823)

## 1. 概要 / 背景
Cloud Run Jobs のタスクアレイ実行（5並列等）において、担当ジョブ数が少ない、または処理が早く完了したタスク（コンテナ）が、全ジョブ完了後も以下のような要因でプロセスを終了せず、無駄なコンテナ稼働時間（課金）が発生していた：
1. 全タスクが完了時に `db_summary`（全20社以上×全種別の24時間新規取得件数）の重いカウントクエリを一斉に実行している。
2. `monitor_error_pages.py` などの重複した監視スクリプトを全タスクが同期実行している。
3. `run_pipeline.py` において Worker タスクが `return` 後に明示的な `sys.exit(0)` を呼ばず、バックグラウンドリソースや待機でコンテナ終了が遅延していた。
4. 全5タスクが個別に実行状況レポートをSlackへ5通送信しており、通知が冗長かつ非効率であった。

本改修では、**B案（クローリングタスク内で完結：最後に終了したタスクが全体集計＆レポート送信を実行し、先に終わったタスクは即時終了）**を採用し、コスト削減とクリーンな終了シーケンスを実現する。

## 2. ユーザーストーリー
* **ユーザーとして**、Cloud Run Jobs のタスクアレイでクローラーを実行する際、
* **目的**: 割り当てジョブが終了したコンテナインスタンスが待機や不要な全体集計を行わず即座に正常終了（exit 0）し、最後に完了した1タスクのみが全体集計・レポート送信を行うようにしたい
* **なぜなら**: 不要なコンテナ稼働時間・課金を最小限に抑え、Slackレポートを1通に集約して可視性を高めるため。

## 3. 機能要件 (FR)
- **FR-001 (自タスク結果の確実な保存)**: タスクアレイ実行時、自タスクの割り当てジョブが完了した時点で、自タスクの実行結果（ステータス、成功数、失敗数、JSONサマリー）を DB（`CrawlerTaskExecution`）に即座に更新・コミットすること。
- **FR-002 (先行完了ワーカーの即時 exit)**: 自タスク完了後、他タスクのステータスを確認し、未完了タスク（`RUNNING` 等）が存在する場合は、全体DB集計 (`db_summary`)、Slack総合レポート送信、および `monitor_error_pages.py` の実行をスキップし、即座に `sys.exit(0)` でプロセスを終了すること。
- **FR-003 (最終完了タスクによる集約委譲)**: 自タスク完了後、他タスクが全て終端状態（`COMPLETED` または `FAILED`）であることを検知した場合（自タスクが最後の1台）、代表して全体集計・総合Slackレポート送信およびエラーページ監視を実行し、完了後に正常終了すること。
- **FR-004 (単体タスク実行の後方互換性)**: 単体タスク実行（非タスクアレイモード、`task_count <= 1`）時は、常に全体集計・総合Slackレポート・エラー監視が現行どおり実行されること。
- **FR-005 (ProxySQL 安全停止ガードの維持)**: 最終完了タスクまたは Coordinator は、全タスク終了時のみ共有 ProxySQL の停止判断を行う既存の安全性を維持すること。

## 4. 非機能要件 (NFR)
- **NFR-001 (コンテナ即時破棄)**: 先行完了したタスクは、全ジョブ完了ログ出力後 5 秒以内にプロセスが終了し、Cloud Run の Billable Instance Time を最小化すること。
- **NFR-002 (デッドロック・競合の防止)**: 複数タスクが同時に終了した場合でも、DBトランザクション分離やロック待ちでプロセスがハングしないこと。
- **NFR-003 (堅牢性)**: DB疎通不良時でも、最大リトライやフォールバックによりプロセスが永久ハングせず Fast-Fail または安全終了すること。

## 5. 受入基準 (AC)
- [ ] AC-1: タスクアレイ実行時、自タスクの割り当てジョブ完了後、CrawlerTaskExecution に `COMPLETED` または `FAILED` が記録されること。
- [ ] AC-2: 他タスクが `RUNNING` の場合、先行完了タスクは全体集計をスキップし、`sys.exit(0)` を呼び出して直ちに終了すること。
- [ ] AC-3: 他タスクが全て終端状態の場合、最後のタスクが全体集計およびSlackレポート送信を行い、正常終了すること。
- [ ] AC-4: 非タスクアレイ実行時は常に全体集計・レポートが行われること。
- [ ] AC-5: ユニットテストおよび関連テストが全件合格すること。
