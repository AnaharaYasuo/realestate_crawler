# 要件定義書: 全サイト巡回パイプラインの非同期投げっぱなし（Fire-and-Forget）化

## 1. 概要・背景
現在、住友不動産（sumifu）をはじめとする不動産ポータルサイトのクローラーは、スタートページ（Start）から地域（Region）ページ、地域からエリア（Area）ページ、エリアから一覧（List）ページ、一覧から詳細（Detail）ページへと多段にAPIディスパッチを行っている。

しかし、親プロセスが子プロセスの処理完了を同期的に待機（`_wait_for_local_execution` による `Thread.join` 最大120秒、または `asyncio.gather(*tasks)`）していたため、以下のような重大なボトルネック・障害が発生していた：
1. **タイムアウトによる巡回中断**:
   子ページ（地域・エリア・一覧等）が完了するまで数百秒かかる場合、120秒で親側が `504 LocalTimeout` となり、親の巡回ループや後続エリアの探索が途中で打ち切られる（例: 住友不動産の中古マンションが188件しか取れない原因）。
2. **直列待機によるリソース遊休**:
   一覧ページが次ページ（2ページ目、3ページ目...）を取得する前に、全詳細ページのパース完了やDB保存完了を待機してしまうため、並行性が極めて低くクローリング全体に過剰な時間を要していた。

## 2. 目的
親ページ（Start / Region / Area / List）が子ページ（Region / Area / List / Detail）をディスパッチする際、子の完了をブロッキング待機せず、直ちに「投げっぱなし（Fire-and-Forget）」でリターンして次の探索・ページネーションを前進させる非同期パイプラインを確立する。

## 3. 機能要件 (FR)
- **FR-1: ローカル実行（_handle_local_execution）におけるFire-and-Forget制御**
  - 環境変数 `CRAWLER_FIRE_AND_FORGET=true`（デフォルト有効）の環境下で、ローカルAPIディスパッチ時にワーカースレッドの開始を確認後、スレッド完了を同期待機（`_wait_for_local_execution`）せず即座に `(detail_url, 200, "FireAndForgetLocal")` を返す。
  - スレッドはバックグラウンド（daemon=True）で独立実行され、完了時にDBコネクションクリーンアップ（`close_old_connections()` / `connections.close_all()`）を確実に実行する。
- **FR-2: HTTP呼び出し（_fetch）との整合性**
  - HTTPディスパッチ時も既に存在する `FireAndForget` 処理（リクエスト送信完了確認後に即時200復帰）と挙動を統一する。
- **FR-3: 中間ページ（MiddlePage）およびスタート（Start）の親ブロッキング解除**
  - 親ページが子APIを呼ぶ際（`_callApi`）、同期ブロッキングせずディスパッチを即座に投げて次へ進む。
  - 重複ディスパッチ防止（`_claim_detail_dispatch` / `_current_dispatch_keys()`）はスレッド安全に維持し、同一URLの二重取得を防止する。
- **FR-4: 後方互換性とテスト容易性**
  - 単体テスト等で同期完了を待機したい場合は `CRAWLER_FIRE_AND_FORGET=false` または `LOCAL_EXECUTION_TIMEOUT_SEC > 0` かつ明示的設定で従来の同期待機動作へ切り替え可能とする。

## 4. 非機能要件 (NFR)
- **NFR-1: DB接続リーク防止**:
  - バックグラウンド実行される全スレッド・タスクにおいて、終了時（正常終了・例外発生時問わず）に Django の DB コネクションが確実にクローズされること。
- **NFR-2: メモリ安定性**:
  - 親ページが子の完了を待たずに次ページへ進む際、参照を保持し続けないよう適切なスコープ管理・GC回収を行う。
