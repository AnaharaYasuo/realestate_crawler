# 要件定義書: 健美家パーサーにおける用語解説欄による築年月・スペック上書き破壊の防止 (Issue #926)

## 1. 背景と課題
健美家 (`kenbiya`) の物件詳細ページには、上部の正規物件スペック欄（`div.property`）の他に、ページ下部に各項目の用語解説欄（`<div class="box_outline">...建物が完成した年月を表示。新築の場合は新築マークを表示。</div>` 等）が配置されている。
パーサー基底クラス (`KenbiyaParserBase._get_specs`) において、ページ内の全 `<dl>` を走査する過程で、下部の用語解説 `<dl>` が正規スペック `<dl>` の後に走査され、`specs["築年月"]` 等のキーが用語解説文で上書きされていた。
この結果、日付変換関数が `None` を返し、健美家の全物件レコードにおいて `chikunengetsu`（築年月）が `None` となるデータ欠損不具合が発生していた。

## 2. 目的
健美家詳細ページからスペック情報を抽出する際、正規スペック領域（`div.property`）配下の要素のみを対象とし、用語解説（`box_outline`, `guide_outline` 等）によるスペック破壊を物理的に防止する。

## 3. 要件一覧
* **REQ-KENBIYA-001**: `_get_specs` は用語解説・ガイド領域（`box_outline`, `guide` を含む親要素）配下の `<dl>` / `<table>` を走査対象外とし、正規スペック情報（`div.property` 内等）のみをスペック辞書に抽出すること。
* **REQ-KENBIYA-002**: 同一キーが複数回走査された場合であっても、先に出現した正規スペック値を優先し、後続の要素による上書きを防止すること。
* **REQ-KENBIYA-003**: 既存のパース項目（価格、間取り、面積、構造、利回り等）にデグレを発生させないこと。
