# 要件定義書: 一覧から詳細ディスパッチのキューワーカー化（5000件）と住友1000件廃止・ページング対応 (#993)

## 1. 概要・背景
大規模仲介サイト（三井のリハウス、住友不動産ステップ、東急リバブル等）において、中間一覧ページが配下の詳細ページ処理を同期待機（`asyncio.gather` & `_handle_local_execution`）していたため、120秒のローカル実行タイムアウト（`LOCAL_EXECUTION_TIMEOUT_SEC`）に抵触し、中間一覧ページごと強制終了する障害が発生していた。また、住友不動産販売において `limit=1000` を付与した過大URLリクエストが行われていたため、サーバー負荷とレスポンス遅延を招いていた。

## 2. 目的
1. **一覧 ➔ 詳細ディスパッチの非同期キューワーカー化**:
   - 一覧ページは詳細URLをキュー（上限5000件）に投入して即座に次のページ巡回へ進む。
   - バックグラウンドワーカーがキューからURLを取り出して詳細パースを実行する。
   - ワーカー数は各クラスの並列数（`DETAIL_PARALLEL_LIMIT` / `semaphore`）に制限され、並列数爆発やOOMを防止する。
2. **住友不動産販売の1000件一括取得の廃止とページネーション対応**:
   - `getAreaDestUrl` から `limit=1000` を排除し、通常のページング（次へリンク）で順次取得する。

## 3. 受入基準 (Acceptance Criteria)
- [ ] **AC-1**: 一覧ページから詳細ページへのディスパッチが非同期キュー（上限5000件）経由で実行され、一覧ページが詳細パース完了を同期待機しないこと。
- [ ] **AC-2**: 詳細パースの並列数がクラス設定値（`DETAIL_PARALLEL_LIMIT` / `semaphore`）を超えないこと。
- [ ] **AC-3**: 住友不動産販売のArea URLに `limit=1000` が付与されず、通常ページングで次ページを辿れること。
- [ ] **AC-4**: 既存の回帰テストおよび単体テストが全件合格すること。
