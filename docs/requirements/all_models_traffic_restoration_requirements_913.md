# 全サイト全モデル欠損データ（traffic等）包括的復旧 要件定義書 (Issue #913)

## 1. 概要
本要件定義は、特定サイト（三井・大京・住友林業・東急）にとどまらず、システム内に存在する全サイト（20社以上）の全物件モデル（マンション・戸建て・土地）を対象として、既存カラムから交通情報（traffic）を安全に再合成・包括復旧するバッチ機構の要件を定義する。

## 2. 目的
1. **全サイト全モデルの網羅的データ復旧**: 手動登録・固定リストではなく、Django のアプリレジストリから `traffic` および交通系カラムを持つ全モデルを動的検出し、全件復旧を実現する。
2. **多経路（Route 1〜5 および バス停1〜5）の完全合成**: 単一の駅（Route 1）のみならず、複数路線・バス停情報を含むすべての交通データを欠落なく合成する。
3. **本番運用の安全性（Zero Production Direct Mod）**: 本番DBに対する直接操作を遮断するハードガード（`assert_production_db_safety`）を維持しつつ、ドライランモードと実更新モード（`--execute`）を安全に提供する。

## 3. 要件一覧
- **REQ-913-001 (Dynamic Model Discovery)**: Django アプリレジストリから `traffic` カラムおよび交通系フィールド（`station` / `railway` 等）を持つ全物件モデルを動的に抽出して走査対象とすること。
- **REQ-913-002 (Multi-Route Synthesis)**: 交通情報の合成ロジックにおいて、Route 1〜5 の駅・沿線・徒歩分数およびバス停1〜5の情報を重複なく結合し、完全な交通文字列を生成すること。
- **REQ-913-003 (Dry-Run by Default)**: デフォルト実行時はDB更新を行わず、復旧対象件数のみを走査・ログ出力すること。`--execute` 付与時のみ安全検証の上で実更新を行うこと。
- **REQ-913-004 (Bulk Update & Safety Guard)**: チャンク単位の `bulk_update` を用いて高速かつ低負荷にDB更新を行うこと。また本番DBへのローカル直接更新は `assert_production_db_safety` で確実にブロックすること。

## 4. アクセプタンスクライテリア
- [ ] `restore_missing_traffic_data.py` が全サイトのモデルを網羅的に走査対象とすること。
- [ ] Route 1〜5 および バス停情報から正しい交通文字列が合成されること。
- [ ] ローカル環境からの本番DB直接更新がブロックされること。
- [ ] 単体テストにおいて全モデル検出・合成ロジック・バッチ実行ロジックが 100% 合格すること。
