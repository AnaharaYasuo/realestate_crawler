# 中間ページ差分更新ストリーミング要件定義書 (Issue #886)

## 1. 背景・目的
一覧・中間ページ探索時に対象サイトの掲載件数が多い場合（1,000件等）やネットワーク遅延がある場合、全物件の探索が完了して詳細ディスパッチが開始されるまで DB レコードの書き込み（新規登録・更新）が 0 件のままとなる。
この間、`crawler_watchdog` が「600秒間 DB 増分なし」としてプロセスを沈黙・ハングと誤判定し、`SIGKILL`（Exit Code: -9）で強制終了してしまう事象を防止する。

## 2. 機能要件
- **FR-886-001: 200件チャンク即時ストリーミング更新**
  - 中間・一覧ページから物件URL（ListItem）を抽出する際、抽出リストが 200 件（`DIFFERENTIAL_CHUNK_SIZE = 200`）に達するごとに、既存かつ価格未変更の物件を抽出し `updateDateTime` をバルク更新する。
- **FR-886-002: 端数（200件未満）の最終フラッシュ**
  - ページ探索完了時点でバッファに残存している端数アイテム（200件未満）も漏れなく `updateDateTime` をバルク更新する。
- **FR-886-003: Watchdog 進捗監視との完全同期**
  - 200件ごとの更新によって DB の `updateDateTime` が順次前進し、`get_count_for_job`（15秒ポーリング）で活動中として検知され、ハング誤判定を回避する。
