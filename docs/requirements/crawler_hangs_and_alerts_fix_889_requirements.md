# 要件定義: クローラーハング誤検知防止および包括的パース不整合自動修復 (Issue #889)

## 1. 概要 / ユーザーストーリー
* **ユーザーとして**、不動産クローラー監視・運用担当者
* **大規模サイトのクロール中に正常な一覧取得がハングと誤判定されて強制終了される事象を防ぎ、かつ三井・アットホーム・旭化成ヘーベルハウス等のパース不整合（必須項目欠損）を解消したい**
* **なぜなら**、不要な強制終了によるクロール中断およびアラートSlackチャンネルのノイズ・再クロール要求の大量発生を撲滅するため

## 2. 課題と受入基準 (Acceptance Criteria)

### A. クローラーウォッチドッグ (ハング誤検知防止)
* [ ] **AC-1**: 初回一覧取得時（DB記録件数 0件時）は、開始から `INITIAL_DISCOVERY_GRACE_SEC`（1800秒）まで `check_job_hung` でハング判定とみなさず、探索を継続できること。
* [ ] **AC-2**: 1件でもDBレコードが記録された後は、通常の `HANG_THRESHOLD_SEC`（600秒）の無進捗判定が適用されること。

### B. 非物件URLの除外
* [ ] **AC-3**: `/support/`, `/mikata/`, `/guide/`, `/manual/`, `/column/` 等のガイド・マニュアルURLが `baseParser._is_non_property_href` で除外判定されること。

### C. 三井パーサー
* [ ] **AC-4**: 三井戸建で `madori`（間取り）が抽出されること。
* [ ] **AC-5**: 三井詳細ページで `item.traffic` が明示的に設定され、最寄り駅/交通のテーブル外スペックからのフォールバック抽出が行われること。
* [ ] **AC-6**: 三井戸建の接道幅員・接面において全角記号（`ｍ`）や `約` プレフィックス表記が正しく抽出されること。
* [ ] **AC-7**: 三井マンションで複合表記（`所在階 / 階建` 等）やラベルから所在階（`kaisu` / `kaisuStr`）が欠損なく抽出されること。

### D. アットホームパーサー
* [ ] **AC-8**: アットホーム戸建で `madori`（間取り）が抽出されること。
* [ ] **AC-9**: アットホーム詳細ページで「完成時期」や「建築年月」等の表記揺れからも築年月がフォールバック抽出されること。

### E. 旭化成ヘーベルハウスパーサー
* [ ] **AC-10**: ヘーベルハウス詳細ページでH2/H1が存在しない場合でも、`<title>` タグから物件名がフォールバック抽出され、空文字にならないこと。
