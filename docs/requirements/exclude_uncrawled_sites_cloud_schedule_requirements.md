# クラウド定期実行（スケジュール）における未巡回サイト除外要件定義書 (Issue #880)

## 1. 概要 / ユーザーストーリー
* **ユーザーとして**: クラウド運用管理者・開発者として
* **目的**: 健美家（`kenbiya`）および中堅仲介4社（`ietan`, `haseko`, `adcast`, `toho`）について、ポータルサイト（`athome`, `homes`）と同様に、日次のクラウドスケジュール定期本番実行の対象外とし、手動指定やローカル実行時のみに限定して実行できるようにする。
* **価値**: クラウド本番の夜間パイプライン（Task 0〜4）の限られた実行時間・リソース枠（Cloud Run Job / ProxySQL）を圧迫せず、安定した基幹巡回（大手5社・信託3社・電鉄系）を確実に完遂させる。

## 2. 機能要件 (FR)

### FR-880-001: クラウド定期スケジュール実行における未巡回サイトの自動除外
- ポータルサイト（`athome`, `homes`）をスキップする仕組みと同様に、未巡回サイト群（`kenbiya`, `ietan`, `haseko`, `adcast`, `toho`）をクラウド定期実行時のデフォルト対象外とする。
- `run_all_crawlers.py`, `run_pipeline.py`, `run_ml_pipeline.py`, `run_bulk_ml_evaluation.py`, `targets.py` において、`skip_uncrawled` フラグ（または `skip_portals` と同様のデフォルト除外オプション）を適用し、通常スケジュール実行時にこれらを除外する。

### FR-880-002: 引数・個別指定時の柔軟な実行保証
- CLI引数（`--sites`, `--company`）で明示的に指定した場合、またはフラグを無効化した場合は、ローカル実行および手動実行で対象サイトの巡回・評価が可能であること。

### FR-880-003: クラウドオーケストレーション（Terraform / Workflows）連携
- `terraform/scheduler.tf` および `terraform/workflows/daily_pipeline.yaml` において、未巡回サイトの除外設定が正しく反映され、日次スケジュール実行時にコンテナが対象サイトを巡回しないこと。

## 3. 非機能要件 (NFR)
- **NFR-880-001 (リソース保護)**: クラウド本番環境における余分なコンテナ稼働時間・DB接続負荷をゼロにする。
- **NFR-880-002 (後方互換性)**: 既存のユニットテスト・総合テストへの影響を局所化し、All Green を維持する。
