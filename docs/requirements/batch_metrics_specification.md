# バッチ処理標準メトリクス表示要件定義書 (Batch Metrics Specification)

## 1. 概要・背景
不動産クローラーおよび価格推定パイプラインにおける主要バッチ処理（学習処理、価格推定処理、割安物件配信処理）において、これまでログおよびSlack通知の表示フォーマットが個別かつ不揃いであり、対象件数、処理件数、所要時間、スループット等の運用監視上不可欠なメトリクスが不足していた。

本仕様は、世間一般のエンタープライズバッチ処理・ML/ETLパイプライン（AWS Batch、GCP Cloud Batch、Airflow、Databricks等）のベストプラクティスに基づき、3大主要バッチ処理における標準バッチメトリクス体系を定義し、ログおよび通知の透明性とトレーサビリティを確立する。

---

## 2. 目的・価値
1. **処理量・進捗の可視化**: バッチが処理した対象総数、完了数、スキップ数、除外数を一目で把握可能にする。
2. **パフォーマンス劣化の早期検知**: スループット（件/秒）および平均レイテンシ（ms/件）を記録し、DB負荷やネットワーク遅延、モデル推論ボトルネックを客観的に検知可能にする。
3. **運用の意思決定支援**: 割安物件配信において、スクリーニング対象候補件数と基準合致件数、配信先チャンネル別内訳を明示し、配信基準の妥当性を迅速に判断可能にする。

---

## 3. 対象バッチ処理および必須メトリクス要件

### 3.1 共通標準メトリクス要件
すべてのバッチ処理において、以下の基本メトリクスを共通で保持・出力すること：
- **実行コンテキスト**: バッチ名、実行開始日時（JST）、実行終了日時（JST）、総所要時間（フォーマット: `X時間Y分Z秒` または `X.X秒`）
- **件数会計 (Volume Accounting)**: 対象総件数 (`total_count`)、処理完了件数 (`processed_count`)、スキップ件数 (`skipped_count`)、エラー/除外件数 (`failed_count`)、処理達成率/成功率 (`success_rate` %)
- **スループット (Throughput)**: 処理速度 (`items/sec` または `ms/item`)

### 3.2 学習処理 (ML Training: `train.py`)
- **対象データ規模**: DBから取得した全物件件数、重複除外後件数
- **物件種別別メトリクス (mansion, kodate, tochi, apartment)**:
  - 投入サンプル件数、外れ値除外後有効学習件数
  - サンプル重み付け適用情報（Time Decay半減期）
  - アルゴリズム別評価指標（LightGBM, XGBoost, CatBoost, RandomForest）: MdAPE (%), MAE (万円), R², RMSE
  - 最適アンサンブル重み比率 & アンサンブルMdAPE
  - スミアリング補正係数 (Smearing Factor)
  - 生成モデルファイル一覧および保存先パス
  - 種別ごとの学習所要時間および全体所要時間

### 3.3 価格推定処理 (Bulk ML Evaluation: `run_bulk_ml_evaluation.py`)
- **対象規模**: 対象モデル数、対象総物件数 (`evaluated_count + skipped_count`)
- **処理結果内訳**:
  - 推定完了件数 (`evaluated_count`)
  - 評価済スキップ件数 (`skipped_count`)
  - 1次スクリーニング通過件数 (`passed_count`)
  - 投資評価件数 (`investment_evaluated_count`)
  - 重複検知除外件数 (`duplicate_count`)
- **スループット**: 推論スループット (`件/秒`)
- **失敗情報**: 失敗モデル一覧およびエラー概要

### 3.4 割安物件配信 (Hot Property Recommendation: `send_recommendations.py`)
- **スクリーニング規模**: スクリーニング対象候補総数 (`total_scanned`)
- **抽出・選別内訳**:
  - 配信判定基準合致件数 (`matched_count`: 割安度20〜35% または 投資スコア≥80点)
  - 配信上限枠 (`quota`: 15件)
  - 配信成功件数 (`sent_count`)
  - 配信失敗件数 (`failed_count`)
- **チャンネル別配信内訳**: マンション、戸建、土地、投資アパート、投資戸建ごとの配信件数
- **配信所要時間**: 配信処理開始から完了までの時間

---

## 4. 受入基準 (Acceptance Criteria)
1. `train.py` 実行時に、学習データ規模、種別ごとの交差検証メトリクス、所要時間、出力先パスが構造化されたサマリーバナーとして標準出力/ログに記録されること。
2. `run_bulk_ml_evaluation.py` 実行時に、対象総件数、完了件数、スキップ件数、1次通過件数、スループット、所要時間がログおよびSlack完了通知に漏れなく出力されること。
3. `send_recommendations.py` 実行時に、対象候補件数、合致件数、配信上限、配信成功件数、チャンネル別配信内訳、所要時間がログおよびSlack完了通知に漏れなく出力されること。
4. 単体テストおよびテスト環境下においてSlack誤送信が遮断され、フォーマット生成関数が100%テスト検証されること。
