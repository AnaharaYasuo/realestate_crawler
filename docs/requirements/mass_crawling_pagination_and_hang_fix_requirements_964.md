# 要件定義書: 全クローラーのページネーション・上限キャップ・ハング根絶と大量クローリング対応

## 1. 概要・背景
現在のクローラーにおいて、三井のリハウス、住友不動産ステップ、野村の仲介+、東急リバブル、athome、homes、smtrc、電鉄系（西武・相鉄・京成等）、ハウスメーカー系（ハイム・積水等）などで、以下の問題により本来数万件〜数千件あるはずの掲載データが数件〜数百件しか取得できない、あるいは0件失敗/ハング強制終了（hung_timeout）している：
1. **ページネーションの中断・セレクター破損**: 「次へ」リンクの抽出失敗により1ページ目のみで早期終了。
2. **検索上限キャップによる切り捨て**: 東急マンション（100件）など、広域一括検索によるサイト側の上限キャップ抵触。
3. **無進捗ハング（hung_timeout / 600秒）**: 三井戸建・大京土地等で、特定ページ応答待ち・無限ループによるプロセス強制終了。
4. **WAF/Bot検知・接続エラー**: athome、homes、smtrc等でジョブ起動失敗または早期遮断。

## 2. 目的
- 全サイト・全物件種別のページネーション・上限キャップ・ハング・WAFエラーを根絶する。
- 数件〜数ページの簡易確認にとどまらず、数百〜数千件単位の大量クローリングが安定して完走できることを実証する。

## 3. 受入基準 (Acceptance Criteria)
* **AC-1**: 全対象サイト（三井・住友・野村・東急・athome・homes・smtrc・電鉄系・ハウスメーカー系等）の次ページ取得セレクターおよび終了判定が正常動作し、全ページを完走すること。
* **AC-2**: 検索上限（100件等）が存在するサイトにおいて、市区町村や条件分割等により上限を超えて全物件を網羅取得できること。
* **AC-3**: 600秒間無進捗ハングが根絶され、適切なタイムアウトと重複防止が適用されていること。
* **AC-4**: 実機環境において大量クローリング（大量ページ送り）が正常動作すること。
* **AC-5**: 単体テスト・回帰テスト・Sonar/Snyk静的解析を全件パスし、本番（production）へリリース完了すること。
