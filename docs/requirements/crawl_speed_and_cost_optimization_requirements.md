# クローリング高速化およびCloud Runコスト最適化 要件定義書 (Issue #851)

## 1. 概要 / ユーザーストーリー
* **ユーザーとして**: 不動産クローラー運用管理者として
* **目的**: クローラーパイプラインの実行時間を大幅に短縮し、Cloud Run コストを最小化（月額無料枠内維持）する
* **価値**: 現在、特定重層サイトの直列巡回、固定低並行度（5固定）、一覧での差分スキップ不可、ロングテールタスクの偏りにより日次実行が9時間タイムアウト・月額課金超過（¥8,000超）を引き起こしている。これを1時間以内に短縮し、Cloud Run実請求額をほぼ¥0に抑制する。

## 2. 機能要件 (FR)

### FR-851-001: 一覧ページでの物件価格抽出と差分スキップの完全連動
- 大京穴吹不動産（`daikyoParser`）等の主要パーサーにおいて、一覧ページから物件URLに加えて「販売価格（`price`）」を抽出し、`ListItem(url=link, price=price)` を返却すること。
- `filter_differential_items` と連動し、DBに登録済かつ価格変動がない物件（全体の80〜90%）は詳細ページのHTTPリクエストを一切発行せずにスキップすること。

### FR-851-002: 都道府県別一覧巡回の非同期並行化および安全ページ上限
- `daikyoParser` における47都道府県の巡回処理（`parseRootPage` / `_crawl_pref_url`）を、直列 `for` ループから `asyncio.gather` によるセマフォ制御（最大5〜8並行）へ移行すること。
- 各都道府県の一覧ページネーションに対し、無限巡回や過去アーカイブの不要取得を防止する安全ページ上限（デフォルト30ページ）を設けること。

### FR-851-003: AdaptiveConcurrency動的並行度の全面採用と固定値制約の撤廃
- Terraformの `CLOUD_DETAIL_CONCURRENCY="5"` 固定環境変数を撤廃（または動的算出優先）とし、`AdaptiveConcurrencyController` による自動動的並行度算出を標準とすること。
- 単独ジョブ時や相手先サイトのWAF許容範囲内で、最大15〜20の並行詳細取得を安全に実行できること。

### FR-851-004: 8タスク分散の再バランシング（ロングテール解消）
- `task_distribution.py` において、Task 4に集中していた重いサイト（大京、ハウスメーカー系）を、比較的短時間で完了するTask 0〜2等へ再配置し、全8タスクの終了所要時間を平準化すること。

## 3. 非機能要件 (NFR)
- **NFR-851-001 (実行時間短縮)**: 日次クローラーパイプラインの全体実行所要時間が、従来の9時間（タイムアウト）から **1時間以内** に短縮されること。
- **NFR-851-002 (コスト抑制)**: Cloud Runの月間消費量が無料枠（180,000 vCPU秒, 360,000 GiB秒）に収まり、Cloud Runの実請求額が ¥0 または ¥500 未満に抑えられること。
- **NFR-851-003 (タイムアウトおよびリソース保護)**: クローラーJobのタイムアウト上限を9時間から **2時間（7200s）**、メモリ上限を3Giから **2Gi** に縮小すること。
