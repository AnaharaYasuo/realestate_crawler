# Cloud定期実行ポータル除外および件数順優先処理 要件定義書 (Issue #985)

## 1. 概要
- **背景**:
  1. Cloud環境（Cloud Run Jobs / Cloud Workflows / Cloud Scheduler）での日次定期実行において、ホームズ（`homes`）およびアットホーム（`athome`）の物件掲載件数は他サイトに比べ桁違いに多く、Cloud環境のメモリ制限やタスク実行時間上限（3時間/10800秒）を圧迫して未完走やタイムアウトを誘発する主因となっていた。
  2. ポータルサイトは大量のIP分散やブラウザ負荷を伴うため、Cloud上の定期バッチではなく、ローカル本番実行（専用端末）で切り分けて集中的に巡回する運用とする。
  3. 各端末（Cloud Runの各タスクコンテナ、およびローカル実行時）において、割り当てられたジョブをアルファベット順等の単純順序で起動するのではなく、**物件件数の多い大規模サイトから先に先行処理を開始**することで、実行時間の長い重いジョブが終盤に残って全体の終了時間を引き延ばす「ロングテール問題（コンテナの待ちぼうけ）」を解消する。

- **目的**:
  - `IS_CLOUD=true` の実行環境において、明示的な `--skip-portals` 引数が与えられていない場合でも自動的にポータルサイト（`homes`, `athome`）をスキップする安全策をビルトイン化。
  - ローカル実行環境（`IS_CLOUD` 未設定）では、フルセット（全104ジョブ）または指定ジョブでの本番巡回を可能に維持。
  - 各実行端末（`run_all_crawlers.py`）で担当ジョブを**「件数の多いサイト・種別優先」**の重み順にソートしてジョブキューに投入し、重いジョブから最優先で先行起動させる。
  - 集約レポート（`pipeline_coordinator.py`, `run_ml_pipeline.py`）において、Cloud定期実行時（5タスクまたは8タスク）にポータル除外後の実効ジョブ数を母数として正確に評価し、未実行誤警報を排除する。

---

## 2. 業務要件・ユースケース

### UC-1: Cloud日次定期実行でのポータル自動スキップ
- Cloud Workflows / Cloud Run Jobs 上で起動される `run_pipeline.py`, `run_all_crawlers.py`, `run_ml_pipeline.py`, `run_bulk_ml_evaluation.py` は、環境変数 `IS_CLOUD=true` を検知した際、`skip_portals` のデフォルト値を `True` として扱う。
- これにより、万一 Cloud Scheduler や手動の gcloud コマンド等で `--skip-portals` を付け忘れた場合でも、Cloud上でのポータル暴走実行を防止する。

### UC-2: ローカル本番実行でのポータルフル巡回
- ローカルマシン（開発機・専用クローリング端末）上では `IS_CLOUD` が未定義であるため、従来の動作通りデフォルトで全104ジョブ（`homes`, `athome` を含む）が巡回対象となる。
- 明示的に `--skip-portals` を付与した場合はローカルでもスキップ可能。

### UC-3: 各端末での「件数多 ➔ 少」優先スケジューリング (Longest-Job-First)
- 各端末（ローカルまたは各タスクコンテナ）に割り当てられたジョブキューは、実行開始前に以下のサイト規模・件数優先順位に従って降順ソートされる：
### UC-3: 各端末での「大手仲介優先 ➔ マンション優先」の2軸優先スケジューリング
- 各端末（ローカルまたは各タスクコンテナ）に割り当てられたジョブキューは、実行開始前に以下の2軸優先順位タプル `(is_major_broker, is_mansion)` に従って降順ソートされる：
  1. **大手仲介 × マンション** `(1, 1)`（最優先）
  2. **大手仲介 × その他種別** `(1, 0)`（戸建て・土地・投資用）
  3. **その他仲介 × マンション** `(0, 1)`
  4. **その他仲介 × その他種別** `(0, 0)`
- 大手仲介グループ: 主要5社（三井・住友・東急・野村・ミサワ）、信託3社（三井住友信託・三菱UFJ・みずほ）、大京穴吹。
- これにより、各端末の並行ワーカースロットが空いた瞬間、最も物件数が多い大手仲介およびマンションから順次投入され、パイプライン末尾の遊休時間を最小化する。

## 3. 受入基準 (Acceptance Criteria)

- [ ] **【基準1】Cloud環境でのポータル自動スキップ**:
  - `IS_CLOUD=true` または `CRAWL_SKIP_PORTALS=true` の環境において、CLI引数で明示指定しなくても `run_pipeline.py`、`run_all_crawlers.py`、`run_ml_pipeline.py`、`run_bulk_ml_evaluation.py` が自動的に `skip_portals=True` で動作すること。
- [ ] **【基準2】ローカル環境でのデフォルト維持**:
  - `IS_CLOUD` が未設定の環境では、引数未指定時のデフォルトが `skip_portals=False` となり、104ジョブすべてが実行可能であること。
- [ ] **【基準3】集約レポート母数と整合性**:
  - Cloud実行時（5タスクまたは8タスク）に、集約レポートの母数がポータル除外後の実効ジョブ数（82件または96件）と完全合致し、未実行誤警報が発生しないこと。
- [ ] **【基準4】大手仲介優先・マンション優先の2軸ソート**:
  - `run_all_crawlers.py` の `job_queue` が、「大手仲介優先 ➔ マンション優先」の2軸でソートされ、各端末で大手仲介およびマンションから先に先行して処理が開始されること。
- [ ] **【基準5】品質・CI検証**:
  - ユニットテストおよび統合テストがすべてパスし、`master` ➔ `production` への本番リリースが完了すること。
