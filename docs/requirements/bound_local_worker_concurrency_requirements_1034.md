# ローカルバックグラウンドワーカー多重度制限 要件定義書 (Issue #1034)

## 1. 背景・課題
- 一覧ページから大量にディスパッチされる詳細URLに対して無制限に `threading.Thread` を起動する Fire-and-Forget 設計により、プロセスあたり800本以上のOSスレッドが滞留。
- スレッドスタック領域および各スレッドが個別に生成する `asyncio.EventLoop`、`ClientSession`、DB接続がメモリを圧迫し、6GB以上のメモリ・スワップ枯渇（`Cannot allocate memory`）およびWSL2クラッシュを招く。

## 2. 目的・要件
- ローカルバックグラウンド実行（`_handle_local_execution`）において、同時に稼働するスレッド数を上限（デフォルト20）に制限する。
- 上限を超えるディスパッチリクエストは軽量なセマフォまたはキューにより待機させ、先行タスクが完了し次第順次実行する。
- ルート処理終了時の待機機構（`_wait_for_active_fire_and_forget_threads`）は、待機中タスクも含めてすべて完了するまで正常に待機する。
- 環境変数 `CRAWLER_LOCAL_WORKER_CONCURRENCY` により同時実行上限数を柔軟にチューニング可能とする（デフォルト: 20）。
