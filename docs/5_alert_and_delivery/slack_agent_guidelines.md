# Slack 24/7 常駐型自動応答エージェント仕様書

## 1. 概要
本仕様書は、Antigravity AI エージェントが Slack 経由で投げられた各種開発指示・調査リクエスト・バッチ実行コマンドに対し、24時間365日無停止で自律受領し、スレッド内へプログレッシブに途中経過・完了報告を連投追記するための動作仕様および設計プロトコルを定義します。

---

## 2. アーキテクチャと返答要否判定プロトコル

### 2.1 先頭識別子（Prefix Identifier）による無帰還判定
ボットによる自動返信が受領イベントとして再キャッチされ無限ループを起こす問題を防ぐため、Agent が Slack に送信するすべてのメッセージの先頭に以下の確定識別子を配置します。

| 識別子 | 用途 | 説明 |
|---|---|---|
| `[AGY-RESP:START]` | タスク開始通知 | メッセージ検知・受領直後に即時レスポンス |
| `[AGY-RESP:PROGRESS]` | 途中経過追記 | バッチ/テスト実行中のプログレッシブ途中ログ |
| `[AGY-RESP:FINISH]` | タスク完了報告 | 最終ステータス (100% SUCCESS / Error) 報告 |

- **判定ルール**: 受信した Slack メッセージの先頭が `[AGY-RESP:` で始まる場合、投稿者（ユーザー/ボット）に関わらず「結果報告メッセージ」とみなして応答処理を即時スキップします。
- **人間ユーザーの無制限受領**: 先頭に識別子が含まれない人間ユーザーからの投稿は、文章の文言に関わらず 100% 無条件で受領・応答開始します。

## 3. 動的段階的通知間隔（Dynamic Progressive Interval）

長領域のバッチ処理やクローリング実行時にメッセージ投稿数が爆発するのを防ぐため、投稿回数に応じて通知間隔を自動拡張するバックオフ制御を採用しています。

```
[投稿 1〜3 回目] :  3秒間隔 (タスク開始直後のクイックフィードバック)
[投稿 4〜6 回目] : 10秒間隔 (安定進行中の定期報告)
[投稿 7〜9 回目] : 30秒間隔 (中長期処理のログ集約)
[投稿 10回目以降] : 60秒間隔 (長時間バッチ・クローリングのスマート通知)
```

## 4. 24/7 自動常駐 ＆ Watchdog 構成

- **プロセスマネージャー**: `run_slack_agent_background.vbs` 内の無限ループ Watchdog (`Do ... WScript.Sleep 2000 ... Loop`) が `slack_agent_host.js` のプロセス状態を監視。
- **自動復旧**: 万が一 node プロセスが異常終了・クラッシュした場合も、2秒後に全自動で即時再起動します。
- **スタートアップ登録**: Windows スタートアップ (`shell:startup`) にショートカットを配置し、PC 起動時および IDE 終了後も無停止待機を実現。
