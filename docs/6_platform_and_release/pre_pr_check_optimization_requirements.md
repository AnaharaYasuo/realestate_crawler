# 変更ファイル動的選別・pre_pr_check 並列最適化 要件定義書 (Issue #579)

## 1. 概要と背景
PR作成およびプッシュ前検証（`pre_pr_check.py` / `.githooks/pre-push`）において、変更内容と無関係な全テスト実行、CodeRabbit等の外部APIレート制限によるブロック、直列実行による待機時間、長大な出力ログによるAIトークン消費が開発リードタイムの深刻なボトルネックとなっていた。本仕様はこれらをシステム的・アルゴリズム的に解消するための要件を定める。

## 2. 機能要件 (FR)
- **FR-001 (変更ファイル種別によるテスト動的選別)**:
  - Markdown / ドキュメントのみの変更時は、コードテスト（pytest, mutation, Sonar, Checkov等）をすべて自動スキップすること。
  - Terraform / IaC のみの変更時は、Python単体テスト・ミューテーションテスト・SonarCloudをスキップし、Checkov / IaCスキャンのみを実行すること。
  - Pythonコードを含む変更時のみ、pytestおよびPRミューテーションテストを実行すること。
- **FR-002 (並行ディスパッチとミューテーション直列性の厳守)**:
  - 時間のかかるテスト実行（pytest）を先行して非同期（バックグラウンドスレッド）でキックし、静的解析（Linter, Sonar, Checkov）と並行処理すること。
  - ファイル直接書き換えを伴うミューテーションテスト（`run_mutation_testing.py`）は、テスト先行ジョブが成功した後にのみ安全に直列実行すること。
- **FR-003 (既存PR追加プッシュ時の外部API自動スキップ)**:
  - 現在のブランチに紐づくオープンなPRが存在する場合、時間とレートリミットを消費するCodeRabbit CLIレビューを自動スキップすること。
- **FR-004 (actionlint の導入と CodeRabbit スコープ除外)**:
  - GitHub Actions ワークフロー（`.github/workflows/**`）の構文検証ツールとして `actionlint` を導入・連携すること。
  - `.coderabbit.yaml` の `path_filters` に `!.github/workflows/**` および `!terraform/**` を追加し、トークン浪費と誤検知を根絶すること。
- **FR-005 (トークン消費削減・サマリー出力圧縮)**:
  - 成功時は1〜2行の最小サマリーのみを出力し、失敗時も長大なスタックトレースではなくエラー行・指摘箇所の要約ブロック（Cavemanスタイル）に圧縮すること。
- **FR-006 (レートリミット Soft Fail 保証)**:
  - CodeRabbit CLI のレートリミット（429 / Monthly limit）検知時は、プッシュやPR作成をブロックせず Warning として安全にスルーすること。

## 3. 非機能要件 (NFR)
- **NFR-001 (検証速度)**: ドキュメント修正時のローカル検証を3秒以内、Terraform修正時を10秒以内に完了すること。
- **NFR-002 (互換性)**: ホスト環境（Windows/Linux/macOS）およびDockerコンテナ内の双方で同一ロジックが安全に動作すること。
