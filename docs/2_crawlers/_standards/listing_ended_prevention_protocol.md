# 掲載終了確定プロトコルと誤認防止仕様 (Listing Ended & False Positive Prevention)

## 1. 概要と背景
サイト側が一時的なWAF制限・Bot検知（HTTP 403/429/503）、または一時的なネットワーク断でエラー画面を返した際、システムがそれを「物件が掲載終了した」と誤認してDB上のステータスを `closed` に落としてしまう「誤掲載終了（False-Closed）」事故を完全に防止する。

---

## 2. 状態判定マトリクス

HTTPステータスおよびHTMLコンテンツに基づいて、以下の3状態に厳密に分類する。

| 判定状態 | 条件・シグナル | システムの振る舞い |
| :--- | :--- | :--- |
| **`DEFINITIVE_CLOSED`**<br>(確定掲載終了) | 以下のいずれかを満たす場合：<br>1. ページ内に明確な掲載終了文言（「この物件の掲載は終了しました」「ご指定の物件は見つかりませんでした」「成約御礼」）が存在する<br>2. 404 Not Found かつ HTMLが正規の404ページ（サイトの共通ヘッダー・フッターを含む）である | ・例外を出さず正常終了<br>・DBステータスを `closed` に更新<br>・Slackアラート除外 |
| **`SUSPECTED_BLOCK`**<br>(一時的ブロック・WAF遮断) | 以下のいずれかを満たす場合：<br>1. HTTP 403 Forbidden, 429 Too Many Requests, 503 Service Unavailable<br>2. HTML内に WAF シグナル（Cloudflare, Akamai, Captcha, "Access Denied", "ワンタイムパスワード"）が存在する<br>3. 白紙ページ（Body長が極端に短い） | ・**掲載終了とは絶対に判定しない**<br>・サーキットブレイカーを発火させ、リトライキューへ退避<br>・FatalアラートをSlackへ通知 |
| **`RETRY_REQUIRED`**<br>(要再確認) | 一覧からリンクが消えているが、詳細URLは 200 OK で表示されている場合 | ・直ちに変更せず、3回連続巡回で存在しないことを確認してから `closed` へ遷移 |

---

## 3. 多重確認（クロスバリデーション）ルール

1. **単発エラーでの `closed` 禁止**:
   - 詳細URLへの単一リクエストが 404 や接続エラーとなった場合でも、初回到達不可時はステータスを `temporary_unreachable` とする。
   - 連続する 2 回以上の巡回バッチで同一結果（または確定掲載終了文言）が確認された時点で初めて `closed` に倒す。
2. **一覧ページ消失判定との連動**:
   - 一覧ページから物件リンクが消失し、かつ詳細ページでも `DEFINITIVE_CLOSED` が確認された場合に、信頼度 100% の掲載終了と認定する。
