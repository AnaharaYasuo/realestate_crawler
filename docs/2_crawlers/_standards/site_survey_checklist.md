# クローラー対象サイト 事前調査チェックリスト (Site Survey Checklist)

新規サイトのクローラーおよびパーサーを実装する前に、必ず本チェックリストに従ってサイト側の構造・通信仕様を調査し、確認結果を記録すること。推測での実装を禁止し、客観的事実に基づいて開発方式を確定させる。

---

## 1. ページレンダリング方式の判定 (Rendering Strategy)

ブラウザ（Chrome DevTools）および `curl` を用いて、対象サイトのHTML生成方式を判定する。

- [ ] **静的 HTML 判定 (Static HTML)**:
  - コマンド検証: `curl -s -A "Mozilla/5.0" "<詳細ページURL>" | grep -i "<価格や物件名>"`
  - [ ] HTMLソース内に物件名、価格、スペック表（所在地・面積等）がテキストとして直接含まれているか？
  - 判定結果: **含まれる ➔ 静的パース方式採用 (`aiohttp` + `BeautifulSoup`)**。目標処理時間: **1,000ms 以内/件**。
- [ ] **動的 JS 描画判定 (Client-Side Rendering / SPA)**:
  - ブラウザのDevToolsで「JavaScriptを無効化」してリロードし、情報が表示されるか確認。
  - [ ] 空の `<div id="app"></div>` やローディング表示のみになり、データが取得できないか？
  - 判定結果: **JS描画必須 ➔ Playwright方式採用**。目標処理時間: **5,000ms 以内/件**。
- [ ] **内部 JSON API / XHR の有無**:
  - Network タブで、詳細データや一覧データを返す非同期 JSON/REST API（`fetch` / `xhr`）が存在するか？
  - [ ] HTMLをパースするより高速かつ安定して取得可能な JSON エンドポイントがあるか？

---

## 2. URL体系と一覧ページネーション構造 (URL & Pagination)

一覧巡回（クロール）の開始点および次ページへの遷移規則を特定する。

- [ ] **物件種別ごとのベースURL / ルーティング**:
  - [ ] マンション: _____________________________________________
  - [ ] 戸建て: _________________________________________________
  - [ ] 土地: ___________________________________________________
  - [ ] 投資用（一棟・区分）: _____________________________________
- [ ] **ページネーション (ページ送り) 方式**:
  - [ ] **URLパス型** (例: `/page/2/`, `/p2/`)
  - [ ] **クエリパラメータ型** (例: `?page=2`, `?p=2`, `?offset=20`)
  - [ ] **次へリンク (`a.next`) 巡回型** (HTML内の次ページURLを相対/絶対取得)
  - [ ] **POST / Ajax 無限スクロール型** (Formデータ送信またはトークンによるカーソル遷移)
- [ ] **取得件数の上限・総件数表示**:
  - [ ] 1ページあたりの表示件数: _____ 件
  - [ ] 検索結果の最大表示上限: _____ 件（上限がある場合、都道府県・市区町村単位の絞り込みURL分割が必要）

## 3. 物件詳細ページのデータ構造 (Data Structure)

パーサーがスペックを抽出するDOM構造の特徴を特定する。

- [ ] **スペック表のタグ形式**:
  - [ ] `<table>` 構造（`tr` > `th` と `td`）
  - [ ] `<dl>` 構造（`dt` と `dd`）
  - [ ] `<div>` グリッド構造（クラス名によるキー・バリュー対応）
  - [ ] JSON-LD (`<script type="application/ld+json">`) の有無
- [ ] **キー（項目名）の探索安定性**:
  - [ ] `th` や `dt` のテキスト（「所在地」「専有面積」「築年月」等）で辞書化（`_get_specs`）可能か？
  - [ ] 表記揺れ（例: 「土地面積」vs「敷地面積」、「交通」vs「アクセス」）の存在確認。
- [ ] **表記フォーマットと単位**:
  - [ ] 価格: 数字と単位（「3,500万円」）が同一タグか、別タグ（`span.amount` + `span.unit`）か。
  - [ ] 面積: `㎡`, `m2`, `坪` の表記規則。バルコニー面積が専有面積と合算されていないか。
  - [ ] 権利形態: 「所有権」「借地権（旧法・普通・定期）」「地上権」の記載形式。
  - [ ] 接道状況: 「幅員」「接面長（間口）」「方角」「公私区分」が1つのセルにまとめられているか。

---

## 4. 掲載終了・非公開時の挙動 (Listing Ended Behavior)

非公開物件・募集終了物件にアクセスした際のHTTP応答とHTML内容を確認する。

- [ ] **HTTPステータスコード**:
  - [ ] `404 Not Found` が返る
  - [ ] `301` / `302` で一覧ページやトップページへリダイレクトされる
  - [ ] `200 OK` のまま「掲載終了」画面が表示される
- [ ] **画面内の掲載終了キーワード**:
  - [ ] 「この物件の掲載は終了しました」
  - [ ] 「ご指定の物件は見つかりませんでした」
  - [ ] 「成約済」
  - ※プロジェクト規約: 掲載終了時は例外を発生させず、Slack通知を除外し、ステータスを `closed` として正常終了させること（NFR-020）。

---

## 5. アンチスクレイピング・アクセス制限対策 (Bot Protection)

アクセス遮断・IPブロックを防ぐための通信制約を確認する。

- [ ] **WAF / Bot対策製品の導入有無**:
  - [ ] Cloudflare / AWS WAF / Akamai / Incapsula のチャレンジ（CAPTCHA、JavaScript検知）が出るか？
- [ ] **必須ヘッダー要件**:
  - [ ] `User-Agent`（PCブラウザ偽装が必須か）
  - [ ] `Referer`（一覧ページからの遷移ヘッダーが必須か）
  - [ ] `Cookie`（セッション維持や同意クッキーが必要か）
- [ ] **安全なリクエストレート**:
  - [ ] リクエスト間隔（推奨: 1.0秒〜2.0秒）
  - [ ] 同時接続数上限（推奨: 最大2並行以下）
  - ※プロジェクト規約: 連続3回以上のタイムアウト時はサーキットブレイカーにより即座に中断すること。
