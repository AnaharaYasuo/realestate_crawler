# 仕様書: Issue #1311 二段階スクリーニング（ML一次選抜50件×種別 ➔ 定性評価スコアリング二次選抜5件×種別）の実装

## 1. 背景と目的
従来のお宝物件通知処理（`send_recommendations.py`）では、機械学習による価格推定・割安率の定量判定（一次スクリーニング）のみで上位15件を選定し、選定された15件に対してのみGemini AIによる定性コメント（レポート）を生成して配信していた。
本改修では、AIの定性コメント付与対象を拡大し、定性評価（投資レーティング AAA/AA/A/B や定性スコア）の優劣を加味して最終配信対象を厳選する**二段階スクリーニングアーキテクチャ**へ刷新する。

## 2. 要件定義 (Requirements)

### 2.1 対象物件種別のグルーピング
以下の4つの主要物件カテゴリ（種別グループ）ごとに処理を行う：
1. **マンション (`mansion`)**
2. **戸建て (`kodate`)**
3. **土地 (`tochi`)**
4. **投資用 (`investment` / `investmentapartment` / `investmentkodate` / `apartment`)**

### 2.2 一次スクリーニング (Stage 1: ML割安度・定量的選抜)
- 各種別グループごとに、機械学習予測価格に基づく割安度（`priority` / 割安率 / 安全弁ガードクリア）の上位**50件**をピックアップする。
- 候補総数: 最大 50件 × 4カテゴリ = 200件。

### 2.3 二次スクリーニング (Stage 2: AI定性評価・スコアリング)
- 一次スクリーニングで抽出された各カテゴリの候補物件（最大50件）に対し、Gemini AIによる多面プロ鑑定評価・団長講評・定性レーティング（AAA, AA, A, B）および定性スコアの算出を行う。
- **レートリミット対策**:
  - API呼び出し間の安全なインターバル待機（例: 1.0〜1.5秒）を挟む。
  - レートリミットエラー（HTTP 429）や一時エラー（503等）発生時は既存の指数バックオフ＋Retry-After待機により自動リトライ。
- **総合スコアリングによる選抜**:
  - 一次スコア（ML割安度優先度）と二次スコア（定性レーティング: AAA=100, AA=85, A=70, B=50 等）を重み付け統合し、各カテゴリごとに上位**5件**を最終配信対象として選抜する。
  - 最終配信総数: 最大 5件 × 4カテゴリ = 20件。
- 一次スクリーニングで評価されたが最終5件に入らなかった物件についても、生成されたAIレポート（講評・レーティング）はDB（`PropertyEvaluation`）に保存・永続化され、将来の参照や次回以降の再利用を可能とする。

### 2.4 Slack配信 & DB永続化
- 二次選抜された各カテゴリ5件（計最大20件）を対応するSlackチャンネル（`goodproperty-mansion`, `goodproperty-kodate`, `goodproperty-tochi`, `goodproperty-invest-*` 等）へ配信。
- 配信完了物件は `is_slack_notified = True` を設定しDB保存。

## 3. アーキテクチャ設計

```
[未通知・公開物件プール]
        │
        ▼ (Stage 1: ML定量評価 _evaluate_candidate)
[種別ごと 上位50件 ピックアップ (計 最大200件)]
        │
        ▼ (Stage 2: Gemini定性評価 & レートリミット制御)
[多面鑑定・団長講評・レーティング生成 & DB永続化]
        │
        ▼ (定性評価加味ソート _select_top_by_qualitative)
[種別ごと 上位5件 最終選抜 (計 最大20件)]
        │
        ▼ (Slack Dispatch)
[Slack 各チャンネル配信 & is_slack_notified更新]
```

   - レートリミット制御およびフォールバック時の安全性検証。
