# 仕様書: Issue #1565 割安物件通知一次スクリーニングにおける乗降客数非公開・データなし駅の足切り仕様書

## 1. 概要 (Overview)
- **背景**:
  Issue #1552 において、乗降客数が 10,000人 未満の過疎駅および最寄り駅から徒歩15分以上の物件を足切りする一次フィルタを導入した。
  しかし、国土数値情報等において乗降客数が「非公開」または「データ未登録」となっている駅については、誤判定防止のためフェールセーフとして通過させていた。
  ユーザーからの要望により、乗降客数が非公開またはデータが存在しない駅についても、流動性・資産性が確認できないリスク物件として一次フィルタで足切り除外（厳格化）を行う。
- **目的**:
  - 徒歩圏内（14分以内）の有効駅に乗降客数データが1件も存在しない（全て `None` またはデータ未登録）物件を一次スクリーニングで足切り除外する。
  - 徒歩圏内に1日1万人以上の乗降客数が確認できる主要駅が1つでもあれば合格とする。
  - 乗降客数が判明している駅がすべて1万人未満の場合は従来どおり足切り除外とする。

## 2. 要件定義 (Requirements)

### 2.1 乗降客数判定ロジックの厳格化
- 対象関数: `src/crawler/scripts/ops/send_recommendations.py:is_depopulated_station_area`
- 判定仕様:
  - 徒歩14分以内の有効なアクセス駅（`accessible_routes`）を取得する。
  - 取得された各駅について `query_station_volume(station_name)` を実行。
  - **合格条件**: 徒歩14分以内の有効駅の中に、`query_station_volume(station_name) >= 10,000` を満たす駅が **1つ以上** 存在すること。
  - **足切り除外条件**: 徒歩14分以内の有効駅の中に、1日1万人以上の乗降客数を満たす駅が **存在しない**（1日1万人未満の過疎駅のみ、または全駅データなし/非公開）場合、`True`（除外対象）を返す。
  - 駅名そのものが物件データに存在しない場合、または駅アクセス経路が0件の場合：
    - 駅情報自体が存在しない物件についても、駅アクセスが確認できないため除外とするか、あるいは従来どおり駅情報なし物件として扱うか。
    - 最寄り駅が特定できない物件は交通利便性が保証されないため、同様に足切り除外（または駅名が存在しない場合も除外）とする。

## 3. テスト計画 (Testing Plan)
- `tests/unit/test_issue_1565_exclude_unknown_station_volume.py`:
  - 乗降客数データが存在しない駅（`query_station_volume` が `None`）の物件が足切り除外されること。
  - 乗降客数1万人未満の駅の物件が従来どおり足切り除外されること。
  - 乗降客数1万人以上の主要駅の物件が通過すること。
  - 複数駅アクセスにおいて、1駅がデータなしでも、もう1駅が1万人以上であれば通過すること。
  - 複数駅アクセスにおいて、データなし駅と過疎駅（1万人未満）のみの場合は除外されること。
  - 既存のテスト（`test_issue_1552_station_filter_recommendations.py`, `test_send_recommendations.py` 等）を新仕様に合わせて更新。
