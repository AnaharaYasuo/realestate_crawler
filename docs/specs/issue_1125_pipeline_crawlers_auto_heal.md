# Issue #1125: クローリングパイプライン障害包括修復 要件定義・仕様書

## 1. 背景・目的
2026-10-28 01:00〜04:00 JSTに本番環境で実行された定期クローリングパイプラインにおいて、以下の複合的な障害が発生した：
1. **reguide**: HTTP 202 Accepted 未対応例外によるプロセス終了 (Exit Code: 1)
2. **smtrc**: WAF 403 対策および Playwright ステルスフォールバック時の極小レスポンス (144 bytes) によるクラッシュ
3. **odakyu / sumai1**: 接続タイムアウトおよび一時的通信エラーによるプロセス全体のクラッシュ (Exit Code: 1)
4. **misawa**: SSL/TLS ハンドシェイク失敗 (`SSLV3_ALERT_HANDSHAKE_FAILURE`) による全種別 0 件取得
5. **sekisui**: 物件一覧抽出セレクタ・URL不一致による全種別 0 件取得
6. **watchdog / 大量物件バックグラウンドスレッド滞留**: fire-and-forget スレッドが数千件滞留し、メインスレッドが無進捗と誤認されて Watchdog (600s) により強制終了 (SIGKILL)

これらを包括的に修復し、パイプラインの安定稼働と耐障害性（Pipeline Resilience）を向上させる。

---

## 2. 外部設計・要件

### 2.1 reguide (HTTP 202 Accepted 対応)
- `baseParser._validate_http_status` において、`200` に加えて `202 (Accepted)` を有効なレスポンスとして許容する。
- 202 の場合、非同期生成レスポンス等として安全にハンドリングする。

### 2.2 smtrc (WAF 回避 & ステルスフォールバック強化)
- WAF（Cloudflare / Akamai / Imperva 等）による 403 遮断を回避するため、リクエストヘッダーを最適化。
- Playwright ステルスフォールバック時、コンテンツサイズが極小（144 bytes等のチャレンジ画面）の場合に即死クラッシュさせるのではなく、一定回数リトライまたは Graceful Skip（サイト一時停止扱い）としてハンドリングし、後続ジョブを道連れにしない。

### 2.3 odakyu / sumai1 (タイムアウト耐障害性向上)
- 中間ページ・個別ページ取得時の連続タイムアウト発生時、プロセス全体をクラッシュさせるのではなく、`SkipPropertyException` 等にフォールバックしてスキップし、他の正常ページのクロールを継続可能にする。

### 2.4 misawa (SSL/TLS ネゴシエーション修復)
- Python の標準 SSL コンテキストの暗号スイート（Cipher Suites）設定を調整し、モダンなサーバー・特定レガシー設定のいずれでも `SSLV3_ALERT_HANDSHAKE_FAILURE` を起こさずセキュアに接続できるようにする。

### 2.5 sekisui (一覧セレクタおよびURL追従)
- 積水ハウス不動産の最新 HTML 構造を精査し、0件取得とならないようセレクタおよびパースロジックを更新。

### 2.6 Watchdog / バックグラウンドスレッド滞留防止
- fire-and-forget キューの滞留時に、定期的に progress touch を更新し、健全にスレッドが消化されている最中に 600 秒無進捗と誤判定されて強制終了されないようプログレス通知を維持する。
