# 仕様書: Issue #1509 投資・実需物件推薦における非現実的異常値（外れ値）安全弁ガードおよびデータ品質防衛仕様書

## 1. 概要 (Overview)
- **事象**:
  三井のリハウス等で取得された投資物件（例: `タキ・コーポラス` 一棟アパート、売出価格9,000万円）において、過去の過渡的・異常な推論レコード（理論予測価格169,922万円、想定積算価格95,465万円、想定賃料11,450.6万円/年、DCF理論価格127,513万円）がDBに残留していた。
- **発生原因**:
  1. Issue #1348 において、二次スクリーニングの存在を前提に一次スクリーニングの割安度上限閾値（`MAX_RECOMMEND_DISCOUNT_PCT` = 60.0% / `MAX_PREDICTION_PRICE_RATIO` = 2.5倍）を撤廃した。
  2. その結果、過去のモデル推論時に一時的に生じた極端な外れ値レコード（売出価格の10倍超やディスカウント率90%超）が一次スクリーニングを無条件で通過するようになった。
  3. AI（LLM）定性鑑定レポート生成時、プロンプトに渡された「積算価格9.5億円」「売出価格9,000万円」をLLMが真に受けて「圧倒的な積算割れ」「本物の歪み物件」と評価し、結果として高スコア（Rating A）が付与されてSlack配信に至った。
- **本改修の目的**:
  1. `send_recommendations.py` の一次選抜（`_evaluate_investment_candidate`, `_evaluate_residential_candidate`）において、現実的な市場取引の範囲を逸脱した極端な外れ値（非現実的異常値）を排除する安全弁ガードを導入する。
  2. 配信直前のオンデマンド積算・DCF算出・モデル予測値の整合性チェックおよび上限ガードを追加する。
  3. DB内の該当異常レコードを最新の数理モデルにより正常値（売出9,000万に対し予測8,013万、積算4,360万、DCF4,354万）へ修正・サニタイズする。

## 2. 要件定義 (Requirements)

### 2.1 推薦配信スクリーニングにおける安全弁（外れ値遮断ガード）の導入
- `send_recommendations.py`:
  - 定数 `MAX_REALISTIC_DISCOUNT_PCT = 85.0` (割安率85%超、すなわち予測価格が売出価格の約6.67倍超となる極端な乖離) を安全弁上限として定義する。
  - `_evaluate_investment_candidate`:
    - `discount_pct >= MAX_REALISTIC_DISCOUNT_PCT` の場合、モデル推論異常・外れ値として除外（スキップログを出力）。
    - また、`eval_rec.estimated_sekisan_price` または `eval_rec.dcf_theoretical_price` が売出価格の 6.0 倍を超えるような極端な積算・DCF歪みがある場合も安全弁として除外する。
  - `_evaluate_residential_candidate`:
    - `discount_pct >= MAX_REALISTIC_DISCOUNT_PCT` の場合、同様に安全弁として除外。
  - これにより、万が一モデル更新の過渡期や未再評価レコードに極端な数字が含まれていても、Slackへ誤配信される事故を100%機械的に防ぐ。

### 2.2 既存DB異常レコードのサニタイズ
- DB上の該当レコード（`PropertyEvaluation` id=270543 等）を最新の決定論的DCFおよびアンサンブル推論モデルで再計算し、正しい数値に更新する（更新完了済み）。

## 3. テスト計画
- `tests/unit/test_send_recommendations.py`:
  - 割安率が85%以上（例: 94.7%割安）の異常レコードが一次スクリーニングで安全弁ガードによってスキップされることを検証するテストケースを追加。
  - 積算価格やDCF価格が売出価格の6倍を超える異常レコードが安全弁によってスキップされることを検証。
  - 正常な割安物件（例: 30%〜60%割安）は従来通り正常に通過することを検証。
- アーキテクチャハーネスおよび既存テストが全てパスすること。
